## 1️⃣ 내장 객체의 개요
*슬라이드 p.6–9 (+ p.23)*

### 내장 객체란
- **내장 객체**(implicit object): JSP 페이지에서 사용할 수 있도록 **JSP 컨테이너에 미리 정의된 객체**
- JSP 페이지가 서블릿 프로그램으로 번역될 때 JSP 컨테이너가 자동으로 내장 객체를 멤버 변수, 메소드 매개변수 등의 각종 참조 변수(객체)로 포함함
- JSP 페이지에 별도의 `import` 문 없이 자유롭게 사용 가능함
- 스크립틀릿 태그나 표현문 태그에 선언을 하거나 객체를 생성하지 않고도 직접 호출하여 사용 가능함

### 내장 객체의 종류 (표 5-1)

| 내장 객체 | 반환 유형 | 설명 |
|---|---|---|
| `request` | `javax.servlet.http.HttpServletRequest` | 웹 브라우저의 HTTP 요청 정보를 저장한다. |
| `response` | `javax.servlet.http.HttpServletResponse` | 웹 브라우저의 HTTP 요청에 대한 응답 정보를 저장한다. |
| `out` | `javax.servlet.jsp.jsp.jspWriter` | JSP 페이지에 출력할 내용을 담고 있는 출력 스트림이다. |
| `session` | `javax.servlet.http.HttpSession` | 웹 브라우저의 정보를 유지하기 위한 세션 정보를 저장한다(13장 참고). |
| `application` | `javax.servlet.ServletContext` | 웹 애플리케이션의 콘텍스트 정보를 저장한다. |
| `pageContext` | `javax.servlet.jsp.PageContext` | JSP 페이지의 정보를 저장한다. |
| `page` | `java.lang.Object` | JSP 페이지를 구현한 자바 클래스로 JSP 페이지 자체를 나타낸다. |
| `config` | `javax.servlet.ServletConfig` | JSP 페이지의 설정 정보를 저장한다. |
| `exception` | `java.lang.Throwable` | JSP 페이지의 예외 발생을 처리한다(11장 참고). |

> [!WARNING]
> **🔍 검증 — 반환 유형의 `javax.*` 표기와 `out` 타입 오타**
> - 표 5-1·5-4와 p.11·p.25 본문은 `javax.servlet...`로 적혀 있지만, 같은 강의자료 p.8의 번역된 서블릿 코드는 `jakarta.servlet...`을 쓰고 실행 화면(p.36)도 `Apache Tomcat/10.1.12`임. Tomcat 10.0부터 명세 API 패키지가 `javax.*` → `jakarta.*`로 바뀌었으므로, Tomcat 11 실습에서는 `jakarta.servlet.http.HttpServletRequest`처럼 `jakarta`로 읽을 것
> - `out`의 `javax.servlet.jsp.jsp.jspWriter`는 오타 — 실제 클래스는 `JspWriter`(대문자 J, 현재 패키지 `jakarta.servlet.jsp`)
> - 근거: [Tomcat 10 마이그레이션 가이드](https://tomcat.apache.org/migration-10.html), [Tomcat 11 JSP API — JspWriter](https://tomcat.apache.org/tomcat-11.0-doc/jspapi/jakarta/servlet/jsp/JspWriter.html)

### 내장 객체는 `_jspService()` 메소드 안에 있음
- 내장 객체는 서블릿 프로그램에서 모두 `_jspService()` 메소드 내부에 있음 (JSP가 번역된 서블릿 코드 일부)

📄 `scripting_jsp.java`
```java
…(생략)…
public final class scripting_jsp extends org.apache.jasper.runtime.HttpJspBase
implements org.apache.jasper.runtime.JspSourceDependent, org.apache.jasper.runtime.JspSourceImports {
…(생략)…
public void _jspService(final jakarta.servlet.http.HttpServletRequest request,
final jakarta.servlet.http.HttpServletResponse response) throws
java.io.IOException, jakarta.servlet.ServletException {
…(생략)…
    final jakarta.servlet.jsp.PageContext pageContext;
    jakarta.servlet.http.HttpSession session = null;
    final jakarta.servlet.ServletContext application;
    final jakarta.servlet.ServletConfig config;
    jakarta.servlet.jsp.JspWriter out = null;
    final java.lang.Object page = this;
    jakarta.servlet.jsp.JspWriter _jspx_out = null;
    jakarta.servlet.jsp.PageContext _jspx_page_context = null;
    …(생략)…
    }
}
```
- **코드 포인트**: ① `request`, `response` → `_jspService()`의 **매개변수로 선언된** 내장 객체 ② `pageContext`, `session`, `application`, `config`, `out`, `page` → 메소드 안에 **미리 선언된 기타 내장 객체** ③ 그래서 스크립틀릿·표현문에서 선언이나 객체 생성 없이 바로 쓸 수 있음

### 속성 처리 메소드 (표 5-2)

| 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `setAttribute(String name, Object value)` | `void` | 해당 내장 객체의 속성 이름이 name인 속성 값을 value로 저장한다. |
| `getAttribute(String name)` | `Object` | 해당 내장 객체의 속성 이름이 name인 속성 값을 가져온다. |
| `removeAttribute(String name)` | `void` | 해당 내장 객체의 속성 이름이 name인 속성을 삭제한다. |
| `getAttributeNames()` | `java.util.Enumeration` | 해당 내장 객체의 모든 속성 이름을 가져온다(단, pageContext 내장 객체는 이 메소드를 제공하지 않는다). |

### 속성을 공유할 수 있는 유효 범위 (p.23)
*슬라이드에서는 request 절 끝(p.23)에 있는 표 — 속성 처리 메소드와 함께 보도록 이 위치로 옮김*

| 영역 | 내장 객체 | 속성의 유효 범위 |
|---|---|---|
| page | `pageContext` | 해당 페이지가 클라이언트에게 서비스를 제공하는 동안 유효하다. |
| request | `request` | 클라이언트의 요청이 처리되는 동안 유효하다. |
| session | `session` | 세션이 유지되는 동안 유효하다. |
| application | `application` | 웹 애플리케이션이 실행되고 있는 동안 유효하다. |

> [!TIP]
> **💡 보충 — pageContext는 `getAttributeNamesInScope(int scope)`를 사용 (JSP API)**
> `PageContext`(부모 클래스 `JspContext`)에는 `getAttributeNames()`가 없는 대신, 영역 상수(`PageContext.PAGE_SCOPE`·`REQUEST_SCOPE`·`SESSION_SCOPE`·`APPLICATION_SCOPE`)를 인자로 받는 `getAttributeNamesInScope(int scope)`가 있음 → 위 표의 4개 영역과 그대로 대응함. 출처: [Tomcat 11 JSP API — PageContext](https://tomcat.apache.org/tomcat-11.0-doc/jspapi/jakarta/servlet/jsp/PageContext.html)

## 2️⃣ request 내장 객체
*슬라이드 p.11–22*

### 1. 요청 파라미터 관련 메소드
**request 내장 객체**
- JSP 페이지에서 **가장 많이 사용되는** 기본 내장 객체
- 웹 브라우저에서 서버의 JSP 페이지로 전달하는 정보 저장
  - 폼 페이지로부터 입력된 데이터를 전달하는 요청 파라미터 값을 JSP 페이지로 가져옴
- JSP 컨테이너는 웹 브라우저에서 서버로 전달되는 정보를 처리하기 위해 `javax.servlet.http.HttpServletRequest` 객체 타입의 request 내장 객체를 사용하여 사용자의 요구 사항을 얻어냄 (패키지명은 1️⃣의 🔍 검증 참고)

**요청 파라미터**(request parameter)
- 사용자가 폼 페이지에 데이터를 입력한 후 서버에 전송할 때 전달되는 폼 페이지의 입력된 정보 형태
- `<name=value>` 형식으로 웹 브라우저에서 서버의 JSP 페이지로 전송됨

**표 5-3 요청 파라미터 관련 메소드의 종류**

| 요청 파라미터 관련 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `getParameter(String name)` | `String` | 요청 파라미터 이름이 name인 값을 전달받는다. 요청 파라미터 값이 없으면 null을 반환한다. |
| `getParameterValues(String name)` | `String[]` | 모든 요청 파라미터 이름이 name인 값을 배열 형태로 전달받는다. 요청 파라미터 값이 없으면 null을 반환한다. |
| `getParameterNames()` | `java.util.Enumeration` | 모든 요청 파라미터의 이름과 값을 Enumeration 객체 타입으로 전달받는다. |
| `getParameterMap()` | `java.util.Map` | 모든 요청 파라미터의 이름과 값을 Map 객체 타입으로 전달받는다[Map 객체 타입은 (요청 파라미터 이름, 값) 형식으로 구성된다]. |

### 🧪 request 내장 객체 사용 예: 요청 파라미터 값 출력하기
📄 `request.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <form action="process.jsp" method="post">
        <p>
            이 름 : <input type="text" name="name">
            <input type="submit" value="전송">
    </form>
</body>
</html>
```
📄 `process.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <%
        request.setCharacterEncoding("utf-8");
        String name = request.getParameter("name");
    %>
    <p> 이 름 :<%=name %>
</body>
</html>
```
- **실행 결과**: `request.jsp`에서 이름(`홍길순`) 입력 후 [전송] → `process.jsp`에 `이 름 :홍길순` 출력
- **코드 포인트**: ① 입력 필드의 `name="name"`이 요청 파라미터 이름 → `request.getParameter("name")`으로 값을 받음 ② `request.setCharacterEncoding("utf-8")` — **폼에서 한글 입력을 정상적으로 처리하려면 반드시 필요함**

### 🧪 [예제 5-1] request 내장 객체로 폼 페이지로부터 아이디와 비밀번호를 전송받아 출력하기
📄 `JSPBook/src/main/webapp/ch05/request01.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <form action="request01_process.jsp" method="post">
        <p> 아 이 디 : <input type="text" name="id">
        <p> 비밀번호 : <input type="text" name="passwd">
        <p> <input type="submit" value="전송" />
    </form>
</body>
</html>
```
📄 `JSPBook/src/main/webapp/ch05/request01_process.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <%
        request.setCharacterEncoding("utf-8");
        String userid = request.getParameter("id");
        String password = request.getParameter("passwd");
    %>
    <p> 아이디 : <%=userid %>
    <p> 비밀번호 : <%=password %>
</body>
</html>
```
- **실행 결과**: `/ch05/request01.jsp`에서 아이디·비밀번호 입력 후 [전송] → `/ch05/request01_process.jsp`에 `아이디 : 관리자`, `비밀번호 : 1234` 출력
- **코드 포인트**: ① 폼의 `action="request01_process.jsp"`, `method="post"`로 처리 페이지에 전송 ② 입력 필드 이름 `id`·`passwd`가 곧 요청 파라미터 이름 → `getParameter("id")`, `getParameter("passwd")` ③ 파라미터를 읽기 전에 `setCharacterEncoding("utf-8")` 호출

> [!TIP]
> **💡 보충 — `setCharacterEncoding()`은 파라미터를 읽기 전에 호출해야 효과가 있음 (Servlet API · Tomcat)**
> - API 문서: 이 메소드는 요청 파라미터를 읽거나 `getReader()`로 입력을 읽기 **전에** 호출해야 함 → 강의 코드처럼 `getParameter()`보다 먼저 써야 함
> - 인코딩을 지정하지 않으면 서블릿 명세의 기본값은 ISO-8859-1임. 다만 Tomcat 10 이후 기본 `conf/web.xml`에는 `<request-character-encoding>UTF-8</request-character-encoding>`이 들어 있어, Tomcat 11에서는 이 호출을 빼도 한글이 깨지지 않을 수 있음 — [예제 5-3]에서 `요청 정보 인코딩 : UTF-8`이 나오는 것도 이 기본 설정 때문
> - 서버 설정에 따라 달라지는 부분이므로 강의대로 직접 호출하는 습관을 유지할 것(시험도 강의 기준)
> - 출처: [Tomcat 11 Servlet API — ServletRequest](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/ServletRequest.html), [Tomcat Wiki — Character Encoding](https://cwiki.apache.org/confluence/display/TOMCAT/Character+Encoding), [Tomcat 기본 conf/web.xml](https://github.com/apache/tomcat/blob/11.0.x/conf/web.xml)

### 2. 요청 HTTP 헤더 관련 메소드
- **요청 HTTP 헤더**: 웹 브라우저는 HTTP 헤더에 부가적인 정보를 담아 서버로 전송함

**표 5-4 요청 HTTP 헤더 관련 메소드의 종류**

| 요청 HTTP 헤더 관련 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `getHeader(String name)` | `String` | 설정한 name의 헤더 값을 가져온다. |
| `getHeaders(String name)` | `Enumeration` | 설정한 name의 헤더 목록 값을 가져온다. |
| `getHeaderNames()` | `Enumeration` | 모든 헤더 이름을 가져온다. |
| `getIntHeader(String name)` | `int` | 설정한 name의 헤더 값을 정수로 가져온다. |
| `getDateHeader(String name)` | `long` | 설정한 name의 헤더 값을 시간 값으로 가져온다. |
| `getCookies()` | `javax.servlet.http.Cookie` | 모든 쿠키 값을 가져온다. |

> [!WARNING]
> **🔍 검증 — `getCookies()`는 쿠키 배열(`Cookie[]`)을 반환**
> API상 시그니처는 `Cookie[] getCookies()` — 요청과 함께 온 모든 `Cookie` 객체를 **배열**로 반환함(패키지는 Tomcat 11 기준 `jakarta.servlet.http`). 근거: [Tomcat 11 Servlet API — HttpServletRequest](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/http/HttpServletRequest.html)

### 🧪 request 내장 객체 사용 예: 요청 HTTP 헤더 정보 값 출력하기
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <%
        String hostValue = request.getHeader("host");
        String alValue = request.getHeader("accept-language");

        out.print("호스트명 : " + hostValue + "<br>");
        out.print("설정된 언어 : " + alValue + "<br>");
    %>
</body>
</html>
```
- **실행 결과**: `호스트명 : localhost:8080`, `설정된 언어 : ko-KR`
- **코드 포인트**: `getHeader("헤더 이름")`으로 특정 헤더 값(`host`, `accept-language`)을 얻고 `out.print()`로 출력

### 🧪 [예제 5-2] request 내장 객체로 모든 HTTP 헤더 정보 값 출력하기
📄 `JSPBook/src/main/webapp/ch05/request02.jsp`
```jsp
<%@ page import="java.util.Enumeration" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <%
        Enumeration en = request.getHeaderNames();
        while (en.hasMoreElements()) {
            String headerName = (String) en.nextElement();
            String headerValue = request.getHeader(headerName);
    %>
    <%=headerName %> : <%=headerValue %><br>
    <%
        }
    %>
</body>
</html>
```
- **실행 결과**(`http://localhost:8080/JSPBook/ch05/request02.jsp`): 브라우저가 보낸 요청 헤더가 `헤더 이름 : 값` 형태로 한 줄씩 모두 출력됨. 슬라이드 화면에는 9개 출력
  - `accept`(이미지·애플리케이션 MIME 유형 목록과 `*/*`), `accept-language : ko-KR`, `cache-control : no-cache`, `ua-cpu : AMD64`, `accept-encoding : gzip, deflate`
  - `user-agent : Mozilla/5.0 (Windows NT 10.0; Win64; x64; Trident/7.0; rv:11.0) like Gecko`, `host : localhost:8080`, `connection : Keep-Alive`, `cookie : JSESSIONID=…`(세션 ID)
  - 출력되는 헤더 종류·값은 사용하는 브라우저에 따라 달라짐
- **코드 포인트**: ① `page` 디렉티브의 `import` 속성으로 `java.util.Enumeration` 임포트 ② `getHeaderNames()`로 모든 헤더 이름을 `Enumeration`으로 받아 `hasMoreElements()`/`nextElement()`로 반복 ③ 이름을 `(String)`으로 형 변환한 뒤 `getHeader(headerName)`으로 값 조회 ④ 스크립틀릿을 `while` 블록 중간에서 닫고(`%>`) 표현문으로 출력한 다음 다시 열어(`<%`) `}`로 닫음 → 표현문 줄이 헤더 개수만큼 반복 출력됨

### 3. 웹 브라우저/서버 관련 메소드
**표 5-5 웹 브라우저/서버 관련 메소드의 종류**

| 웹브라우저/서버 관련 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `getRemoteAddr()` | `String` | 웹 브라우저의 IP 주소를 가져온다. |
| `getContentLength()` | `long` | 웹 브라우저의 요청 파라미터 길이를 가져온다. |
| `getCharacterEncoding()` | `String` | 웹 브라우저의 문자 인코딩을 가져온다. |
| `getContentType()` | `String` | 웹 브라우저의 콘텐츠 유형을 가져온다. |
| `getProtocol()` | `String` | 웹 브라우저의 요청 프로토콜을 가져온다. |
| `getMethod()` | `String` | 웹 브라우저의 HTTP 요청 메소드(GET, POST)를 가져온다. |
| `getRequestURI()` | `String` | 웹 브라우저가 요청한 URI 경로를 가져온다. |
| `getContextPath()` | `String` | 현재 JSP 페이지의 웹 애플리케이션 콘텍스트 경로를 가져온다. |
| `getServerName()` | `String` | 서버 이름을 가져온다. |
| `getServerPort()` | `int` | 실행 중인 서버 포트 번호를 가져온다. |
| `getQueryString()` | `String` | 웹 브라우저의 전체 요청 파라미터 문자열[물음표(?) 다음 URL에 할당된 문자열]을 가져온다. |

> [!WARNING]
> **🔍 검증 — `getContentLength()`의 반환 유형은 `int`**
> - API상 `int getContentLength()` — 요청 **본문**(body)의 길이를 바이트 단위로 반환하고, 길이를 모르면 `-1`을 반환함. `long`을 반환하는 메소드는 `getContentLengthLong()`임
> - 같은 문서 기준으로 `getContentType()`은 본문의 MIME 유형을 모르면 `null` → 본문이 없는 GET 요청인 [예제 5-3]에서 `요청 정보 길이 : -1`, `요청 정보 콘텐츠 유형 : null`이 나오는 이유
> - 근거: [Tomcat 11 Servlet API — ServletRequest](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/ServletRequest.html)

> - IPv4 주소로 확인하고 싶으면 `http://127.0.0.1:8080/...`처럼 IPv4 주소로 접속하면 됨
> - 출처: [RFC 4291 §2.2·§2.5.3](https://www.rfc-editor.org/rfc/rfc4291.html), [RFC 6761 §6.3](https://www.rfc-editor.org/rfc/rfc6761.html)

## 3️⃣ response 내장 객체
*슬라이드 p.25–36*

### 1. 페이지 이동 관련 메소드
**response 내장 객체**
- 사용자의 요청을 처리한 결과를 서버에서 웹 브라우저로 전달하는 정보를 저장하고, 서버는 **응답 헤더**와 **요청 처리 결과 데이터**를 웹 브라우저로 보냄
- JSP 컨테이너는 서버에서 웹 브라우저로 응답하는 정보를 처리하기 위해 `javax.servlet.http.HttpServletResponse` 객체 타입의 response 내장 객체를 사용하여 사용자의 요청에 응답 (패키지명은 1️⃣의 🔍 검증 참고)

**페이지 이동**
- **페이지 이동**(= **리다이렉션**(redirection)): 사용자가 새로운 페이지를 요청할 때와 같이 페이지를 강제로 이동하는 것
- 서버는 웹 브라우저에 다른 페이지로 강제 이동하도록 response 내장 객체의 리다이렉션 메소드를 제공함
- 페이지 이동 시에는 문자 인코딩을 알맞게 설정해야 함

**표 5-6 페이지 이동 관련 메소드의 종류**

| 페이지 이동 관련 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `sendRedirect(String url)` | `void` | 설정한 URL 페이지로 강제 이동한다. |

### 🧪 response 내장 객체 사용 예: 페이지 이동하기

```jsp
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <%
        response.sendRedirect("http://www.google.com");
    %>
</body>

```
- **실행 결과**: `response.jsp`를 실행하면 Google 검색 첫 화면으로 이동함

### 🧪 [예제 5-4] response 내장 객체로 페이지 이동하기
- 아이디·비밀번호를 입력받아 아이디(=관리자)와 비밀번호(=1234)가 일치하면 성공 페이지, 일치하지 않으면 실패 페이지로 이동 (파일 4개)

📄 `JSPBook/src/main/webapp/ch05/response01.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <form action="response01_process.jsp" method="post">
        <p> 아 이 디 : <input type="text" name="id">
        <p> 비밀번호 : <input type="text" name="passwd">
        <p> <input type="submit" value="전송">
    </form>
</body>
</html>
```
📄 `JSPBook/src/main/webapp/ch05/response01_process.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <%
        request.setCharacterEncoding("utf-8");
        String userid = request.getParameter("id");
        String password = request.getParameter("passwd");

        if (userid.equals("관리자") && password.equals("1234")) {
             response.sendRedirect("response01_success.jsp");
        } else {
             response.sendRedirect("response01_failed.jsp");
        }
    %>
</body>
</html>
```
📄 `JSPBook/src/main/webapp/ch05/response01_success.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    로그인을 성공했습니다!!
</body>
</html>
```
📄 `JSPBook/src/main/webapp/ch05/response01_failed.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <p> 로그인을 실패했습니다.
    <p> <a href="./response01.jsp"> 로그인 가기</a>
</body>
</html>
```
- **실행 결과**: `/ch05/response01.jsp`에서 `관리자`/`1234` 입력 → 주소가 `/ch05/response01_success.jsp`로 바뀌고 `로그인을 성공했습니다!!` 출력. 다른 값 입력 → `/ch05/response01_failed.jsp`로 이동해 `로그인을 실패했습니다.`와 **로그인 가기** 링크(→ `response01.jsp`) 표시
- **코드 포인트**: ① 처리 페이지는 화면에 아무것도 출력하지 않고 조건에 따라 `response.sendRedirect()`로 성공/실패 페이지로 보냄 ② 비교 전에 `setCharacterEncoding("utf-8")`을 호출해야 한글 아이디 `관리자`를 올바르게 비교함 ③ 실패 페이지의 `<a href="./response01.jsp">`로 다시 로그인 폼으로 돌아감

> [!TIP]
> **💡 보충 — forward 액션 태그(5주차) vs `response.sendRedirect()` (Servlet·JSP API · Oracle 튜토리얼 · MDN)**
>
> | 구분 | `<jsp:forward page="..." />` | `response.sendRedirect("...")` |
> |---|---|---|
> | 이동 방식 | 서버 **내부**에서 현재 요청을 다른 자원으로 넘김(서블릿 API의 forward 기능 사용) | 서버가 `302 Found` 상태 코드와 `Location` 헤더로 응답 → 브라우저가 그 URL을 **새로 요청** |
> | 요청 횟수 | 1번 | 2번(왕복 1회 추가) |
> | 브라우저 주소창 | 처음 요청한 URL 그대로 | 이동한 페이지 URL로 바뀜 |
> | request 객체 | **원래 request 객체**가 대상 페이지로 전달됨 → 요청 파라미터·request 영역 속성 유지 | 새 요청이므로 이전 요청의 파라미터·request 영역 속성은 이어지지 않음 |
> | 이동 범위 | 같은 웹 애플리케이션 안의 자원 | 외부 사이트도 가능(위 사용 예의 `http://www.google.com`) |
>
> 출처: [RequestDispatcher.forward()](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/RequestDispatcher.html), [PageContext.forward()](https://tomcat.apache.org/tomcat-11.0-doc/jspapi/jakarta/servlet/jsp/PageContext.html), [HttpServletResponse.sendRedirect()](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/http/HttpServletResponse.html), [Oracle Java EE 5 Tutorial — jsp:forward](https://docs.oracle.com/javaee/5/tutorial/doc/bnajc.html), [MDN — Redirections in HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Redirections)

> [!WARNING]
> **⚠️ 보충 — 폼을 거치지 않고 `response01_process.jsp`를 바로 열면 `NullPointerException`**
> `getParameter()`는 해당 파라미터가 없으면 `null`을 반환함(표 5-3) → 처리 페이지를 주소창에서 직접 요청하면 `userid`가 `null`이라 `userid.equals("관리자")`에서 예외가 발생함. 실습은 반드시 폼 페이지(`response01.jsp`)에서 시작할 것 (null에 안전한 비교 예: `"관리자".equals(userid)`). 근거: [Tomcat 11 Servlet API — ServletRequest.getParameter()](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/ServletRequest.html)

### 2. 응답 HTTP 헤더 관련 메소드

- 헤더 정보에는 주로 **서버에 대한 정보**가 저장되어 있음

**표 5-7 응답 HTTP 헤더 관련 메소드의 종류**

| 응답 HTTP 헤더 관련 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `addCookie(Cookie cookie)` | `void` | 쿠키를 추가한다. |
| `addDateHeader(String name, long date)` | `void` | 설정한 헤더 이름 name에 날짜/시간을 추가한다. |
| `addHeader(String name, String value)` | `void` | 설정한 헤더 이름 name에 value를 추가한다. |
| `addIntHeader(String name, int value)` | `void` | 설정한 헤더 이름 name에 정수 값 value를 추가한다. |
| `setDateHeader(String name, long date)` | `void` | 설정한 헤더 이름 name에 날짜/시간을 설정한다. |
| `setHeader(String name, String value)` | `void` | 설정한 헤더 이름 name에 문자열 값 value를 설정한다. |
| `setIntHeader(String name, int value)` | `void` | 설정한 헤더 이름 name에 정수 값 value를 설정한다. |
| `containsHeader(String name)` | `boolean` | 설정한 헤더 이름 name이 HTTP 헤더에 포함되었는지 여부를 확인한다. 포함하고 있는 경우 true를 반환하고, 그렇지 않은 경우 false를 반환한다. |
| `getHeader(String name)` | `String` | 설정한 헤더 이름 name 값을 가져온다. |

### 🧪 response 내장 객체 사용 예: 응답 HTTP 헤더에 정보 추가하기

- **코드 포인트**: `setHeader()`·`addHeader()`·`setDateHeader()`로 응답 헤더를 넣고, `response.getHeader()`로 다시 읽어 출력함

### 🧪 [예제 5-5] response 내장 객체로 5초마다 JSP 페이지 갱신하기
📄 `JSPBook/src/main/webapp/ch05/response02.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8" %>
<html>
<head>
<title>Implicit Objects</title>
</head>
<body>
    <p> 이 페이지는 5초마다 새로고침 됩니다.
        <%
            response.setIntHeader("Refresh", 5);
        %>
    <p> <%=(new java.util.Date()) %>
</body>
</html>
```
- **실행 결과**: `이 페이지는 5초마다 새로고침 됩니다.` 아래에 현재 날짜·시각(예: `Tue Aug 22 18:19:47 KST 2023`)이 출력되고, 5초마다 페이지가 새로 고쳐지면서 시각이 바뀜
- **코드 포인트**: `response.setIntHeader("Refresh", 5)` — 응답 헤더 `Refresh`에 정수 `5`를 설정 → 5초 간격 자동 갱신

> [!TIP]
> **💡 보충 — `set…Header()` vs `add…Header()`, 그리고 `Refresh` 헤더 (Servlet API · MDN)**
> - `setHeader()`·`setIntHeader()`·`setDateHeader()`는 같은 이름의 헤더가 이미 있으면 새 값으로 **덮어씀**, `addHeader()`·`addIntHeader()`는 같은 이름에 값을 **여러 개** 둘 수 있도록 추가함
> - `setDateHeader()`의 날짜 값은 1970-01-01 00:00:00 GMT(epoch)부터의 **밀리초** → 위 사용 예의 `1L`은 epoch 직후(1밀리초)라 `Thu, 01 Jan 1970 00:00:00 GMT`로 표시됨
> - `Refresh: 5`는 페이지가 다 로드된 뒤 5초가 지나면 브라우저가 페이지를 새로 고치게 하는 응답 헤더로, HTML의 `<meta http-equiv="refresh" content="5">`와 똑같이 동작함 → `setIntHeader("Refresh", 5)`가 이 헤더를 만듦
> - 일정 시간 뒤 **다른 URL로 이동**시키려면 `Refresh: 5; url=...` 형식(문자열)이므로 `setHeader("Refresh", "5; url=...")`처럼 문자열로 설정함
> - 출처: [Tomcat 11 Servlet API — HttpServletResponse](https://tomcat.apache.org/tomcat-11.0-doc/servletapi/jakarta/servlet/http/HttpServletResponse.html), [MDN — Refresh](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Refresh)

## 4️⃣ out 내장 객체
*슬라이드 p.38–43*

### 1. out 내장 객체
- 웹 브라우저에 데이터를 전송하는 **출력 스트림 객체**
- JSP 컨테이너는 JSP 페이지에 사용되는 모든 표현문 태그와 HTML, 일반 텍스트 등을 out 내장 객체를 통해 웹 브라우저에 그대로 전달함
- 스크립틀릿 태그에 사용하여 단순히 값을 출력하는 표현문 태그(`<%= … %>`)와 **같은 결과**를 얻을 수 있음

**표 5-9 out 내장 객체 메소드의 종류**

| out 내장 객체 메소드 | 반환 유형 | 설명 |
|---|---|---|
| `print(String str)` | `void` | 설정된 str 값을 웹 브라우저에 출력한다. |
| `println(String str)` | `void` | 설정된 str 값을 웹 브라우저에 출력한다. 이때 줄 바꿈(`\r\n` 또는 `\n`)이 적용되지 않는다. |
| `newLine()` | `void` | 줄바꿈(`\r\n` 또는 `\n`)을 출력한다. |
| `getBufferSize()` | `int` | 현재 출력 버퍼의 크기를 가져온다. |
| `getRemaining()` | `int` | 현재 남아 있는 출력 버퍼의 크기를 가져온다. |
| `clear()` | `void` | 현재 출력 버퍼에 저장되어 있는 내용을 웹 브라우저에 전송하지 않고 비운다. 만약 버퍼가 이미 플러시되었다면 IOException이 발생한다. |
| `clearBuffer()` | `void` | 현재 출력 버퍼에 저장되어 있는 내용을 웹 브라우저에 전송하지 않고 비운다. 만약 버퍼가 이미 플러시되었다면 IOException이 발생하지 않는다. |
| `flush()` | `void` | 현재 출력 버퍼에 저장되어 있는 내용을 웹 브라우저에 전송하고 비운다. |
| `isAutoFlush()` | `boolean` | 출력 버퍼가 채워졌을 때의 처리를 결정한다. 자동으로 플러시하는 경우 true를 반환하고, 그렇지 않은 경우 false를 반환한다. |

> [!WARNING]
> **🔍 검증 — `println()`은 줄바꿈 문자를 실제로 출력함 (화면에서 안 보일 뿐)**
> - JspWriter API: `println(String x)`는 문자열을 출력한 뒤 **줄을 끝냄**(줄 구분자 출력), `newLine()`은 시스템 속성 `line.separator`에 정해진 줄 구분자를 출력함
> - 하지만 브라우저는 HTML 소스의 줄바꿈을 공백으로 바꾸거나 없앤 뒤 화면에 그림 → 화면상으로는 줄이 바뀌지 않음. 표 5-9의 "줄 바꿈이 적용되지 않는다"는 **화면 표시 기준** 설명으로 이해할 것(페이지 소스 보기에서는 줄이 바뀌어 있음)
> - 화면에서 줄을 바꾸려면 아래 사용 예처럼 `<br>` 태그를 함께 출력해야 함
> - 근거: [Tomcat 11 JSP API — JspWriter](https://tomcat.apache.org/tomcat-11.0-doc/jspapi/jakarta/servlet/jsp/JspWriter.html), [MDN — Handling whitespace](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_text/Whitespace)

```jsp
                     <p> <b>출판일</b> : <%=book.getReleaseDate() %>
                     <p> <b>분류</b> : <%=book.getCategory() %>
                     <p> <b>재고수</b> : <%=book.getUnitsInStock() %>
                     <h4><%=book.getUnitPrice() %>원</h4>
                     <p> <a href="#" class="btn btn-info"> 도서주문 &raquo;</a>
                     <a href="./books.jsp" class="btn btn-secondary"> 도서목록 &raquo;</a>
                </div>
   </div>
  <jsp:include page="footer.jsp" />
</div>
</body>
</html>
```
- **실행 결과**: 도서 목록에서 [상세 정보 »]를 누르면 `book.jsp?id=ISBN1235`처럼 해당 도서의 상세 페이지가 열림(그림 5-2 오른쪽)
- **코드 포인트**: ① `page` 디렉티브로 `dto.Book`을 임포트하고, `<jsp:useBean id="bookDAO" class="dao.BookRepository" scope="session" />`으로 `BookRepository` 객체를 `bookDAO`라는 이름으로 사용 ② **request 내장 객체** 활용: `request.getParameter("id")`로 2단계 버튼이 넘긴 도서 ID를 받아 `bookDAO.getBookById(id)`로 `Book` 객체를 얻음 ③ 표현문으로 도서명·설명·도서코드·저자·출판사·출판일·분류·재고수·가격 출력 ④ 메뉴는 include 디렉티브(`menu.jsp`), 바닥글은 include 액션 태그(`footer.jsp`)로 포함하고, [도서주문 »]은 `href="#"`, [도서목록 »]은 `./books.jsp`로 연결

> [!WARNING]
> **⚠️ 보충 — 없는 도서 ID로 열면 `NullPointerException`**
> `getBookById()`는 일치하는 도서가 없으면 `null`을 반환하는데, `book.jsp`는 `book`이 `null`인지 확인하지 않고 바로 `book.getName()`을 호출함 → `book.jsp`를 `id` 없이 열거나 목록에 없는 ID로 열면 예외가 발생함. 실습은 도서 목록의 [상세 정보 »] 버튼으로 들어갈 것

## 🧠 핵심 요약
- **내장 객체** = JSP 컨테이너가 미리 정의한 객체 → `import`·선언·객체 생성 없이 스크립틀릿·표현문에서 바로 사용. 번역된 서블릿의 `_jspService()` 안에 있음(`request`·`response`는 매개변수)
- **9개**: `request`·`response`·`out`·`session`·`application`·`pageContext`·`page`·`config`·`exception`
- **속성 처리**: `setAttribute`·`getAttribute`·`removeAttribute`·`getAttributeNames`(pageContext는 미제공) / **영역**: page(`pageContext`, 페이지 서비스 동안)·request(요청 처리 동안)·session(세션 유지 동안)·application(웹 애플리케이션 실행 동안)
- **request**: 요청 파라미터(`getParameter`·`getParameterValues`·`getParameterNames`·`getParameterMap`), 요청 헤더(`getHeader`·`getHeaderNames` 등), 웹 브라우저/서버 정보(`getRemoteAddr`·`getMethod`·`getRequestURI`·`getContextPath`·`getQueryString` 등). 한글 파라미터는 `request.setCharacterEncoding("utf-8")`을 먼저 호출
- **response**: 페이지 이동 `sendRedirect(url)`, 응답 헤더 `set…Header()`/`add…Header()`(예: `setIntHeader("Refresh", 5)` → 5초마다 갱신), 응답 콘텐츠 `setContentType()`·`setCharacterEncoding()`·`sendError(코드, 메시지)`·`setStatus()`
- **out**: 웹 브라우저로 보내는 출력 스트림 — 스크립틀릿 안의 `out.println(x)`는 표현문 `<%=x %>`와 같은 결과, 화면 줄바꿈은 `<br>`로. 버퍼 관련 `getBufferSize`·`getRemaining`·`clear`·`clearBuffer`·`flush`·`isAutoFlush`
- **북마켓**: `BookRepository.getBookById()` 추가 → `books.jsp`에 `book.jsp?id=…` [상세 정보] 버튼 → `book.jsp`가 `request.getParameter("id")`로 도서를 찾아 상세 정보 출력. `welcome.jsp`는 `Refresh` 헤더로 접속 시각 자동 갱신

| 헷갈리는 쌍 | 구분 포인트 |
|---|---|
| `getParameter()` vs `getParameterValues()` | 값 하나(`String`) vs 같은 이름의 모든 값(`String[]`) — 값이 없으면 둘 다 `null` |
| `setHeader()` vs `addHeader()` | 헤더 이름 name에 값을 **설정** vs **추가** |
| `flush()` vs `clear()` | 버퍼 내용을 웹 브라우저에 **전송하고** 비움 vs **전송하지 않고** 비움 |
| `clear()` vs `clearBuffer()` | 둘 다 전송하지 않고 비움 — 버퍼가 이미 플러시됐으면 `clear()`만 IOException 발생 |
| `sendRedirect()` vs `sendError()` | 설정한 URL로 강제 이동 vs 오류 코드·메시지를 응답 |

## ✍️ 시험 대비 체크포인트
- **Q.** 내장 객체(implicit object)란? → **A.** JSP 페이지에서 사용할 수 있도록 JSP 컨테이너에 미리 정의된 객체. 별도의 `import` 문·선언·객체 생성 없이 스크립틀릿·표현문에서 바로 호출해 사용함
- **Q.** 내장 객체는 번역된 서블릿 프로그램의 어디에 있나? → **A.** 모두 `_jspService()` 메소드 내부 — `request`·`response`는 매개변수로, `pageContext`·`session`·`application`·`config`·`out`·`page`는 메소드 안에 미리 선언됨
- **Q.** `out`, `application`, `page` 내장 객체는 각각 무엇인가? → **A.** `out` = JSP 페이지에 출력할 내용을 담고 있는 출력 스트림 / `application` = 웹 애플리케이션의 콘텍스트 정보 저장 / `page` = JSP 페이지를 구현한 자바 클래스로 JSP 페이지 자체(`java.lang.Object`)
- **Q.** 속성을 공유할 수 있는 4가지 영역과 각 영역의 내장 객체는? → **A.** page–`pageContext`, request–`request`, session–`session`, application–`application`
- **Q.** 속성 처리 메소드 중 `getAttributeNames()`를 제공하지 않는 내장 객체는? → **A.** `pageContext`
- **Q.** 폼에서 전송된 한글을 정상 처리하려면 처리 페이지에서 무엇을 해야 하나? → **A.** 요청 파라미터를 읽기 전에 `request.setCharacterEncoding("utf-8");` 호출
- **Q.** 같은 이름의 요청 파라미터 값을 모두 배열로 받는 메소드와 반환 유형은? → **A.** `getParameterValues(String name)`, `String[]`(값이 없으면 `null`)
- **Q.** 모든 요청 헤더의 이름과 값을 출력하려면? → **A.** `request.getHeaderNames()`로 `Enumeration`을 받아 `hasMoreElements()`/`nextElement()`로 반복하면서 `request.getHeader(headerName)`으로 값 조회([예제 5-2])
- **Q.** 클라이언트 IP, 요청 방식, 요청 URI, 콘텍스트 경로를 얻는 메소드는? → **A.** `getRemoteAddr()`, `getMethod()`, `getRequestURI()`, `getContextPath()` — [예제 5-3]에서 요청 URI `/JSPBook/ch05/request03.jsp`, 콘텍스트 경로 `/JSPBook`
- **Q.** 사용자를 다른 페이지(예: `http://www.google.com`)로 강제 이동시키는 코드는? → **A.** `response.sendRedirect("http://www.google.com");` (페이지 이동 = 리다이렉션)
- **Q.** JSP 페이지를 5초마다 새로 고치게 하는 코드는? → **A.** `response.setIntHeader("Refresh", 5);`
- **Q.** 404 오류 코드와 오류 메시지를 웹 브라우저에 보내는 코드는? → **A.** `response.sendError(404, "요청 페이지를 찾을 수 없습니다");`
- **Q.** `clear()`와 `clearBuffer()`의 차이는? → **A.** 둘 다 출력 버퍼의 내용을 웹 브라우저에 전송하지 않고 비우지만, 버퍼가 이미 플러시되었으면 `clear()`는 IOException이 발생하고 `clearBuffer()`는 발생하지 않음
- **Q.** `out.println("Hello!"); out.println("Jakarta Server Pages 입니다.");`의 화면 출력은? 두 줄로 나오게 하려면? → **A.** `Hello! Jakarta Server Pages 입니다.` 한 줄로 출력됨 → `out.println("Hello!" + "<br>");`처럼 `<br>`을 함께 출력
- **Q.** [북마켓] `book.jsp`는 어떤 도서를 보여 줄지 어떻게 알아내나? → **A.** 도서 목록 버튼 링크 `./book.jsp?id=<%=book.getBookId() %>`로 넘어온 파라미터를 `request.getParameter("id")`로 받아 `bookDAO.getBookById(id)`로 `Book` 객체를 찾음
